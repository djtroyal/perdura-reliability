Mathematical distinctions to preserve

“Effective failure rate” is not one quantity

For a survival function R, no-repair MTTF=∫₀∞R(t)dt. For failure-or-age renewal at T, corrective events per operating time=[1−R(T)]/∫₀ᵀR(t)dt. For a minimal-repair Weibull process, average event rate=H(T)/T. These are different policies. With zero downtime, operating and calendar rates agree. For fixed inspections with failure held until T, the calendar rate is [1−R(T)]/T, while the survival integral measures uptime. A reciprocal MTTF is not generally an instantaneous hazard. Perdura should identify the chosen model before presenting any equivalent MTBF.

Precision and uncertainty describe different things

A quadrature error bound, Monte Carlo sampling interval, parameter confidence interval, predictive count interval and inventory service probability answer different questions. Do not relabel one as another. Reuse exact supported inference and report only the intervals appropriate to the data/stopping model.

Retain stronger methods

Perdura already has mixed-censoring likelihood, all-n exact binomial intervals, exact t-based normal mean inference, qualified Crow-AMSAA inference, advanced spares models and recent renewal/fleet additions. Toolkit conveniences can inspire UI integration without replacing these methods with midpoint approximations or arbitrary normal/Wilson switches. See Concepts18a,19,26 and27 for the source evidence.

Keep uncertain reconstruction explicit

Cold-spare switching and lifetime repair fractions admit distinct dependence models. Observed outputs establish differences, not undocumented implementation intent. The toolkit conditional-mean runtime is correct in the tested case even though its static formula image appears mistyped. Confidence algorithms not revealed publicly remain unverified.

1Effective Failure Rate of "n" Active Redundant Units, with "m" Required for Success (with Repair)Workflow

System reliability

Method and mathematics

Rome Eq.1: q=n−m, μ=1/Mct; λeff≈n! λ^(q+1)/[(m−1)! μ^q], displayed effective MTBF=1/λeff. This approximates a first-failure mean; it is not a constant system hazard or stationary cycle length.

Assumptions and interpretation

Identical constant-rate active units, all initially working, prompt repair, λ small relative to μ. Repair concurrency is not explicit in the calculator; the coefficient matches a single-repair-channel rare-event chain, not the q!-different independent parallel-repair model for q>1. Handbook cautions against delayed maintenance.

Perdura implementation and workflow

Markov Analysis supports explicit states/rates, first-failure reliability and MTTF: src/reliability/Markov.py:395, :440; stationary failure frequency, cycle MTBF and MUT: :498, :511, :535. GUI example models and metrics: gui/frontend/src/components/Markov/index.tsx:1151, :1371. Build an m-of-n repair chain manually; existing TMR example at src/reliability/Markov.py:1010.

Recommended disposition

Partial workflow parity; general solver is stronger. P1 add an m-of-n builder with selectable repair crews, initial condition, and separate first-failure/steady-state metrics. Keep Rome approximation only as a named reference comparison.

Evidence and limits

Page and handbook equation visually verified; one live example λ=.001/h, Mct=100 h, 1-of-2 returns 5000 h. Independent Perdura Markov check gives first-failure MTTF=6500 h, stationary cycle=6050 h, MUT=6000 h. Different metrics are expected, not a Perdura defect.
